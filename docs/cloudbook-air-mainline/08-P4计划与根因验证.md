## 1 安全与刷写 SOP（先立规矩）

### 1.1 硬性边界

- 只允许写 `boot_a` 与 `misc`。
- 严禁触碰 `boot_b`、`uboot_a/b`、`trust_a/b`，以及前 8 MiB `idbloader`。
- 不操作 `<UNRELATED_DEVICE_IP>:5555`（三星手机）。
- 不 `git commit`、不新建分支。
- 串口日志一律落盘到 `logs/`，不覆盖历史日志。

### 1.2 两阶段确认

刷写与重启必须是两个独立动作、两次独立确认：

1. **阶段 A：刷写**
   - 复述目标设备 IP、镜像路径、镜像 SHA-256、目标分区。
   - 用户明确确认后，执行 `flash_candidate_boot_a.sh`。
   - 脚本必须完成：远端推送校验 → `dd` + `fsync` → 读回 SHA-256 比对 → `misc` 写入与校验。
   - 脚本结束必须输出 `Device was NOT rebooted.`，且不得包含任何 `adb reboot`。
2. **阶段 B：重启**
   - 再次向用户复述“将重启设备”，取得独立确认。
   - 才开始串口抓取并执行 `adb -s <IP>:5555 reboot`。
   - 重启后先确认落在 Slot A 的 6.12，再决定是否继续。

### 1.3 脚本改造项（待办）

`flash_candidate_boot_a.sh` 目前仍允许 `FLASH_CONFIRM` 环境变量绕过交互确认，存在与“两次确认”混淆的风险。改造为：

- 删除 `FLASH_CONFIRM` 旁路，或改为显式 `--yes-write` 且打印目标分区；
- 写盘成功后输出结构化的“下一步请单独确认重启”提示；
- 可选增加 `--dry-run`，只打印校验计划。

## 2 4.15 秒复位根因验证（P3 遗留）

### 2.1 目前已证实的结论

| 结论 | 证据 | 状态 |
|---|---|---|
| v1 首个阻塞点是 SDIO Wi-Fi | `dwmmc_rockchip fe2c0000.mmc: card is non-removable.`；v2 禁用 `&sdmmc1` 后越过 | 已验证 |
| v7 在约 4.15 秒、EHCI/OHCI hub 枚举期间整机复位 | v7 串口最后落在 `hub 5-0:1.0` 后出现 DDR/U-Boot 重新初始化 | 已验证 |
| v4 的“CPU DVFS 欠压 / PMIC Latch”根因 | v7 去掉 `cpu-supply` 后仍复位 | 已推翻 |
| WDT 是复位根因 | v8 `cr=0x00000008`（bit0=0，未使能），条件喂狗分支未执行；DTB/配置/initramfs 与 v7 相同 | 未证实，倾向于否定 |
| v8 为何成功 | 仅重建 `dw_wdt.o` 并加诊断，无法解释行为变化 | 未闭环 |

**必须避免的表述**：不能说“v8 加了喂狗所以启动成功”。正确表述是“v8 是首个进入用户态的版本，但复位根因尚未闭环”。

### 2.2 对照实验设计（单变量）

每组只改一个因素，重复至少 2 次；记录复位时刻与最后日志。

| # | Image | DTB | initramfs | cmdline | 目的 |
|---|---|---|---|---|---|
| E0 | v7 | v7 同版 | v7 | 同 v7 | 复现基线，确认 v7 必复位 |
| E1 | v8 | v7 同版 | v7 | 同 v7 | 隔离“仅 Image 变化” |
| E2 | v8 | v8 | v8 | 同 v7 | 复现成功基线 |
| E3 | v8 | v8，`&wdt = disabled` | v8 | 同 v7 | 排除 WDT |
| E4 | v8 | v8，`&wdt = okay` | v8 | `nowatchdog` | 排除内核 watchdog 框架 |
| E5 | v8 | v8，USB 控制器逐个 disabled（EHCI→OHCI→xHCI 分步） | v8 | 同 v7 | 验证 USB 枚举假设 |
| E6 | v8 | v8 | v8 | 拔掉 / 更换 USB 外设 | 验证设备枚举时序影响 |

补充观测项：

- `clk_ignore_unused pd_ignore_unused` 是否仍在 cmdline；
- 复位前 `clk`/`genpd`/ALSA/EHCI/OHCI/hub 的完整时序；
- 复位是否总在同一时间点（4.1~4.2 秒）；
- 冷启动与热重启是否可复现差异；
- 读取复位原因寄存器（若 U-Boot/PMIC 可提供）。

### 2.3 结果表模板

```text
编号 | Image SHA | DTB SHA | initramfs SHA | cmdline | USB 设备 | 最后日志 | 复位时刻 | WDT cr | 结论
```

### 2.4 退出条件

- 找到可稳定复现/稳定规避的单变量；
- 或证明复位与 USB 枚举无因果关系；
- 或确认是 bootloader/PMIC 侧行为，转入 U-Boot 取证。
- 在根因未闭环前，不把任何临时参数当作“正式修复”写入最终镜像。

## 3 P4 外设点亮计划（按依赖链）

顺序原则：先“能看见”，再“能输入”，再“能出声/联网”，最后电源与睡眠。

### 3.1 P4-1 显示链（最高优先）

目标：内屏 BOE NV140WUM-N44 `1920×1200@60Hz` 出图。

步骤：

1. **VOP2**：启用 `vop2`，确认 VP1 → eDP、VP0 → HDMI 的端口映射。
2. **eDP 控制器**：`edp@fe0c0000`，确认时钟、复位、电源域。
3. **eDP PHY**：`edp-phy@fdcb0000`，核对寄存器序列。
4. **Panel**：`panel-simple` / `panel-edp` 的时序与 `power-supply`。
5. **背光**：`pwm8`（`fe6f0000`，25000ns）+ `GPIO2_D3`（gpio91）使能。
6. **面板电源与使能**：`vcc3v3_lcd_edp`（`GPIO2_D5`）、panel enable（`GPIO2_D4`）。
7. **DRM 用户态**：Xorg / Wayland 起图形会话。

**关键风险（阻塞项）**：

- 主线 6.12 中未找到 `rockchip,rk3568-edp-phy` 的 PHY 驱动匹配；
- `rockchip,rk3568-edp` 不在现有 Analogix DP 驱动兼容表中（现有 `rk3288-dp`、`rk3399-edp`、`rk3588-edp`）。

因此显示阶段很可能需要**移植/新增 PHY 驱动或补丁**，不能只改 DTS `status`。先做源码与兼容表核查，再决定补丁范围。

当前配置（模块化，需确认能加载）：

```text
CONFIG_DRM=m
CONFIG_DRM_ROCKCHIP=m
CONFIG_DRM_PANEL_EDP=m
CONFIG_DRM_PANEL_SIMPLE=m
CONFIG_BACKLIGHT_PWM=m
CONFIG_DRM_DISPLAY_DP_HELPER=y
```

验收：`/sys/class/drm/card*-eDP-1` 状态为 `connected`，内屏出现控制台/图形，`modetest` 能设 1920×1200。

### 3.2 P4-2 输入

1. USB 键盘：实际按键产生 `evdev` 事件（`evtest`）。
2. I2C-HID 触控板：`touchpad@2c` 上电、复位、报点。
3. 电源键、霍尔传感器：事件与 `power_supply`/input 节点。
4. 键盘背光：`GPIO2_A1` 开关与亮度。

验收：`libinput debug-events` 能看到键盘、触控板、电源键事件。

### 3.3 P4-3 音频

1. RK809 codec 与 I2S1（`fe410000`）时钟/路由。
2. 扬声器使能 `GPIO3_C3`，耳机检测 `GPIO3_C2`。
3. 当前 `CONFIG_SND_SOC_RK817=m`，确认模块加载与 card 注册。
4. `aplay` 实际出声，插拔耳机切换。

验收：`aplay -l` 有 card；扬声器与耳机均能播放；插拔事件正确。

### 3.4 P4-4 Wi-Fi / 蓝牙

1. MT7663S SDIO：`mmc1` / `fe2c0000`。
2. 固定 1.8V：主线缺少 `zte,sdio-fixed-1-8v` 时会在 CMD11 死锁，需要补丁或替代方案。
3. 电源与复位：`vcc_wl`（`GPIO0_A5`）、BT reset（`GPIO2_B7`）、SDIO pwrseq（`GPIO0_B5`）。
4. 内核配置当前为：

```text
# CONFIG_WLAN is not set
# CONFIG_MT76 ... 
# CONFIG_BT_MTKSDIO is not set
```

5. 先做 SDIO 枚举与固件加载，再做扫描、连接、吞吐。

验收：`iw dev` 有无线接口；`iw scan` 能看到 AP；能连接并跑通吞吐；蓝牙能扫描/配对。

### 3.5 P4-5 摄像头

- USB 摄像头：`uvcvideo` 枚举与取流。
- MIPI 摄像头（如适用）：供电、时钟、lane 数、`media-ctl` 拓扑。
- 验收：`v4l2-ctl --list-devices` 与一帧实际采集。

### 3.6 P4-6 电池 / 充电 / 睡眠

1. BQ25700（`0x6b`）、SC2021（`0x21`）、SBS 电池（`0x0b`）驱动与 I2C 通信。
2. 电池电压、电流、容量、充电状态 sysfs 数值。
3. 适配器插拔事件。
4. `rtcwake -m mem` 进入与唤醒，唤醒后 USB/输入/显示/Wi-Fi 恢复。

验收：sysfs 数值合理；插拔有事件；睡眠能唤醒且外设不丢失。
